اختيار المشاريع و PPM 📊

الشركة عندها طلبات مشاريع أكتر بكتير من الفلوس والناس المتاحين. فاللجنة مش بتقيّم مشروع لوحده.

🖥️ برنامج الـ PPM

PPM software بيجمّع ويدير معلومات كل المشاريع — الشغّالة والمستنية موافقة — وبكده الشركة بتفضل محدّثة وتتكيّف مع الظروف. أهم مميزاته:

Project prioritizationEmployee allocationReal-time project monitoringFlagging cost & time variancesMonitoring economic feasibility
📖 الكتاب بيضيف: الهدف محفظة فيها مزيج: مشاريع high-risk / high-reward (تحويلية) + مشاريع low-risk (صيانة وتشغيل).

الـ Methodology 🧭

قبل ما نبدأ المشروع لازم نختار طريقة الشغل اللي هنمشي بيها.

📖 التعريف

Methodology = a formalized approach to implementing the SDLC — يعني سلسلة خطوات لازم تتنفذ وDeliverables لازم تتطلّع.

🏭 بتيجي منين؟

Internally developed by the organizationConsulting firmsSoftware vendorsGovernment agencies

3 عائلات — اضغط تروح لكل واحدة

الفرق الأساسي: الـ Structured بتفترض إن كل phase تخلص تماماً قبل اللي بعدها (وده بيدّي جودة وانضباط). الـ RAD و Agile هدفهم يوصّلوا جزء شغّال للـ users بدري.

🎯 لعبة: الـ methodology دي من أنهي عائلة؟

Structured — Waterfall · Parallel · V-Model 🏗️

كلها مبنية على الـ SDLC وبتفترض إن الـ phase تخلص قبل ما نبدأ اللي بعدها. الهدف: لو كل phase اتعملت كويس، الناتج هيبقى صح وعالي الجودة.

بنتحرك من phase للتانية زي الشلال، والـ deliverables بتتسلّم من phase للي بعدها.

Planning System request, plan
Analysis System proposal
Design System specification
Implementation Working system

💪 Strengths

  • الـ requirements بتتحدد بدري جداً قبل ما البناء يبدأ
  • الـ requirements متجمّدة (frozen) — مفيش «moving targets»

⚠️ Weaknesses

  • لازم تستنى وقت طويل قبل ما تشوف أي دليل ظاهر على النظام
  • بياخد وقت طويل من البداية للنهاية

نقسّم المشروع لـ subprojects تتشغّل عليها فرق في نفس الوقت ← الوقت الكلي بيقل.

Planning + general designتصميم عام للنظام كله
Subproject 1design → build
Subproject 2design → build
Subproject 3design → build
Integration → final systemنجمّعهم في الآخر

💪 Strengths

  • بيقلل وقت المشروع مقارنةً بالـ Waterfall
  • بيقلل الـ rework: وقت أقصر ← فرصة أقل إن الـ requirements تتغير

⚠️ Weaknesses

  • تقسيم الـ subprojects محتاج قرارات تصميم دقيقة
  • تجميع الـ subprojects في الآخر ممكن يبقى معقد وصعب

بيركّز على جودة النظام من خلال تخطيط الاختبارات: وإحنا بننزل في الـ analysis والـ design، بنصمّم الـ tests اللي هتتنفذ بعدين. (اضغط على أي صف)

RAD — Rapid Application Development ⚡

الهدف: نطوّر جزء من النظام بسرعة ونحطه في إيد الـ users.

🧰 بيستخدم أدوات وتقنيات خاصة

CASE toolsJAD sessionsVisual programming languagesCode generators

التلات أنواع (اضغط على كل واحد)

بنطوّر النظام كـ سلسلة نسخ (versions) ورا بعض. كل نسخة بتتسلّم، والـ users بيجرّبوها، وده بيحدد إيه اللي في النسخة اللي بعدها.

V1core features
V2+ features
V3full system

💪 Strengths

  • الـ users بياخدوا نظام يستخدموه بسرعة
  • بيحددوا احتياجات إضافية للنسخ الجاية من تجربتهم الفعلية

⚠️ Weaknesses

  • الـ users بيستخدموا نظام ناقص لفترة
  • لازم يصبروا لحد النظام الكامل

نعمل نسخة خام وسريعة «quick-and-dirty» ونكبّرها بتحسينات متكررة لحد ما تبقى هي النظام النهائي.

💪 Strengths

  • الـ users بيشتغلوا على الـ prototype بسرعة جداً
  • دورات الـ feedback بتخليهم يحدّدوا التغييرات ويصقلوا الـ real requirements

⚠️ Weaknesses

  • تحليل سطحي ممكن يعمل مشاكل
  • قرارات التصميم الأولى ممكن تبقى ضعيفة
  • features اتنسيت ممكن يبقى صعب تضيفها بعدين

⚠️ Weaknesses

Agile 🏃

تركيز على دورات قصيرة كل واحدة بتطلّع منتج software كامل، وقابلة للتكيّف جداً في البيئات المتغيرة. أشهر نوعين: XP و Scrum.

📜 القيم الأربعة (Agile Manifesto) — من الكتاب

Individuals & interactionsOVERprocesses & tools
Working softwareOVERcomprehensive documentation
Customer collaborationOVERcontract negotiation
Responding to changeOVERfollowing a plan

النوعين (اضغط)

تركيز على الممارسات الهندسية:

✅ Continuous testing 👥 Pair programming — مبرمجين اتنين على جهاز واحد ⏱️ Short iterations 🔧 Relentless refactoring 🙋 Full-time customer representative جوه الفريق

شغل في Sprints ثابتة الطول (2 – 4 أسابيع). كل sprint بيطلّع potentially shippable increment.

📦 Shippable increment

👤 Product Owner

بيدير الـ Product Backlog ويرتّبها بالأولوية.

🧑‍🏫 Scrum Master

بيوجّه الفريق ويشيل العوائق (impediments) اللي بتتذكر في الـ stand-up.

💪 Strengths

  • تسليم سريع للنتايج
  • شغّال كويس لما الـ requirements مش محددة أو بتتغير

⚠️ Weaknesses

  • محتاج انضباط (discipline)
  • مشاركة كبيرة من الـ users ضرورية
  • منحنى تعلّم عالي في الأول
  • الأحسن مع المشاريع الصغيرة

🧠 أنماط تساعدك تحفظ

❓ متطلبات مش واضحة

الـ 3 Structured = Poor. الأحسن: System Prototyping · Throwaway · Agile (Excellent).

🧪 تكنولوجيا غير مألوفة

Throwaway هو الوحيد Excellent. الـ Iterative = Good، والباقي Poor.

🧩 نظام معقد

Throwaway = Excellent. الـ System Prototyping و Agile = Poor.

🛡️ Reliability عالية

V-Model و Throwaway = Excellent. الـ System Prototyping = Poor.

⏱️ وقت قصير

Iterative · System Prototyping · Agile = Excellent. الـ Waterfall و V-Model = Poor.

👀 Schedule visibility

Iterative · System Prototyping · Agile = Excellent. الـ 3 Structured = Poor.

🧠 ملاحظتين: الـ Waterfall عنده 4 خانات Poor — أضعف واحد قدام المتطلبات المتغيرة. والـ Throwaway مفيهوش ولا Poor (بس بياخد وقت أطول).

🧪 جرّب: الأداة تقترح عليك

علّم على خصائص مشروعك وشوف أنهي methodology بتاخد أعلى نقط (Poor = 0 · Good = 1 · Excellent = 2).

⚠️ الأداة مجرد مساعدة للتدريب. في الامتحان برّر اختيارك بالـ ratings: «Waterfall is Poor for unclear requirements...» وبعدين «Throwaway is Excellent for...».

🧪 V-Model pairs

Analysis → Acceptance test · System design → System test · Architectural design → Integration test · Component design → Unit test (execution: Unit → … → Acceptance)

🏃 XP vs Scrum

XP: continuous testing, pair programming, short iterations, refactoring, full-time customer rep. Scrum: 2–4 week sprints, Product Owner, Product Backlog, daily 15-min stand-up, Scrum Master, shippable increment.
